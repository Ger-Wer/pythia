# Руководство по изучению: Claw Arbs и автоматизированный беттинг

Данное руководство предназначено для глубокого изучения принципов работы Claw Arbs — специализированного программного обеспечения для автоматизации арбитражных и валуйных ставок. Документ охватывает технические аспекты, функциональные возможности и ключевые стратегии, описанные в предоставленных материалах.

---

## I. Ключевые концепции и архитектура системы

### 1. Спортивный арбитраж (Sure Bets)
Арбитраж — это стратегия, позволяющая зафиксировать гарантированную прибыль путем одновременного размещения ставок на все возможные исходы события в разных букмекерских конторах (или на рынках предсказаний). Claw Arbs находит ценовые разрывы (гэпы) между площадками (например, Kalshi и Polymarket) и исполняет обе стороны сделки за миллисекунды.

### 2. Валуйный беттинг (Value Betting)
В отличие от арбитража, валуйный беттинг предполагает ставку только на одно плечо, где коэффициент букмекера выше, чем реальная вероятность исхода. 
*   **Sharp Reference:** Claw Arbs использует котировки «острых» (sharp) букмекеров как эталон для определения истинной вероятности.
*   **No-Vig Odds:** Функция очистки эталонных коэффициентов от маржи букмекера для получения максимально точного значения вероятности.
*   **Auto-Sniper Re-fire:** Система отслеживает событие после первой ставки. Если преимущество (edge) увеличивается выше заданного порога, бот автоматически совершает повторную ставку для наращивания позиции.

### 3. Технологическое преимущество и скорость
*   **Прямое подключение:** Использование WebSocket API для Kalshi и Polymarket обеспечивает задержку около 25 мс.
*   **DOM Observation:** Для букмекеров без API используется «безголовый» (headless) браузер. MutationObserver фиксирует изменение коэффициентов за ~20 мс непосредственно на странице, что в десятки раз быстрее сторонних сервисов (задержка которых составляет 500–2000 мс).
*   **Локальное исполнение:** Весь стек (Python/FastAPI, React, Playwright) работает локально на компьютере пользователя. Учетные данные шифруются и не передаются на внешние серверы.

### 4. Настройка и сообщество
*   **Strategy Agents:** Независимые агенты с индивидуальными настройками лимитов, рынков, лиг и порогов доходности (более 30 параметров переопределения).
*   **Point-and-click Calibration:** Инструмент, позволяющий пользователю самостоятельно «обучить» бота читать коэффициенты с любого сайта через CSS-селекторы.
*   **Community Hub:** Платформа для обмена конфигурациями (калибровками) между пользователями, использующая систему вознаграждений за поддержание актуальности настроек.

## II. Вопросы для проверки знаний (краткие ответы)

**1. В чем основное различие между подходом Claw Arbs и традиционными сервисами сканирования коэффициентов?**
*Ответ:* Традиционные сервисы используют сторонние API, которые парсят данные с задержкой 0.5–2 секунды. Claw Arbs работает напрямую с API площадок или через DOM-наблюдатель в браузере, достигая скорости реакции ~20 мс.

**2. Какие три площадки преднастроены в Claw Arbs для работы «из коробки»?**
*Ответ:* Kalshi, Polymarket и Cloudbet.

**3. Что такое «14-ступенчатый конвейер безопасности» (Safety Pipeline)?**
*Ответ:* Это набор проверок перед исполнением сделки, включающий в себя кнопку экстренной остановки (kill switch), отслеживание незакрытых плеч (naked legs), кулдауны, лимиты экспозиции и фильтры дубликатов.

**4. Как работает режим «Снайпер» (Sniper Mode)?**
*Ответ:* Пользователь задает целевой коэффициент и ставку. Бот мониторит все подключенные площадки и исполняет ордер в тот момент, когда цена достигает или превышает заданный порог. Это фактически добавляет функционал лимитных ордеров для букмекерских контор.

**5. Какие технологии используются в программном стеке Claw Arbs?**
*Ответ:* Python и FastAPI для бэкенда, React и TypeScript для фронтенда, Playwright для скрапинга и SQLite для локального хранения данных. Приложение упаковывается в нативные форматы через Nuitka.

## III. Темы для углубленного анализа (эссе)

1.  **Сравнительный анализ арбитража и валуйного беттинга в условиях высокой волатильности рынков.** Используя данные о функциях Auto-Sniper и No-Vig, обсудите, почему валуйный беттинг может иметь более высокую ожидаемую доходность в долгосрочной перспективе, несмотря на отсутствие гарантированной прибыли в моменте.
2.  **Эволюция методов обхода ограничений API через браузерную автоматизацию.** На примере функции калибровки CSS-селекторов и DOM-наблюдения в Claw Arbs, проанализируйте, как локальное выполнение кода решает проблему «хрупкости» скраперов и задержки данных.
3.  **Роль децентрализованного сообщества в поддержании работоспособности торгового ПО.** Рассмотрите модель Community Hub и систему вознаграждений за калибровки как способ борьбы с изменениями верстки на сайтах букмекеров.

## IV. Глоссарий важных терминов

| Термин | Определение согласно контексту |
| :--- | :--- |
| **Edge (Преимущество)** | Математическое превосходство коэффициента над реальной вероятностью исхода. |
| **Soft Bookmaker** | Букмекер с медленной реакцией на изменение рынка, где чаще возникают валуйные ситуации. |
| **Sharp Bookmaker** | Букмекер с наиболее точными коэффициентами, используемый как эталон для оценки вероятности. |
| **Vig (Маржа/Маржа букмекера)** | Комиссия, заложенная в коэффициенты; Claw Arbs предлагает инструменты для её автоматического вычета (No-Vig). |
| **Naked Leg (Незакрытое плечо)** | Рискованная ситуация в арбитраже, когда одна ставка принята, а вторая — нет. |
| **Kelly Criterion (Критерий Келли)** | Математическая формула для определения оптимального размера ставки в зависимости от размера преимущества и банкролла. |
| **Asian Handicap (Азиатский гандикап)** | Вид ставки на исход события с учетом форы, исключающий ничейный результат. |
| **Dutching (Датчинг)** | Стратегия разделения общей суммы ставки между несколькими исходами для получения равной прибыли. |
| **Headless Browser** | Браузер без графического интерфейса, используемый Claw Arbs для высокоскоростного считывания данных с сайтов. |
| **Fak (Fill or Kill)** | Тип ордера, требующий немедленного исполнения всего объема сделки, в противном случае ордер отменяется. |
