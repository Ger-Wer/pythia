# Pythia R4 — архитектурное решение и план

**Дата:** 2026-10-22. **Архитектор:** Muse. **База:** принятый baseline `bc747cd` (весь R3), ветка `codex/evidence-r4-corpus`, checkout `/home/pythia/pythia-evidence-r4`.
**Формулировка карты:** «Размеченный корпус и измерение качества сбора. Ориентир 120 документов + 20 негативных контролей RU/EN/ZH; раздельные настройка/контроль; отчёт ошибок по типам; критические числа корректны либо отклонены; объём не доказывает доходность».

## 1. Что измеряем

Качество СБОРА (не прогнозов): для каждого документа корпуса известно правильное поведение системы (метка), замерщик прогоняет документ через принятые компоненты и сравнивает. Пути измерения по типам документов:

- **Заявления FOMC** → принятый statement extractor: абзацы/доказательства, даты, числа ставки, typed rejection для чужих типов.
- **Ленты и JSON принятых источников** → принятые R3.0 экстракторы и R1-проверки: факты, даты (неизвестная дата = null), числа.
- **Все документы** → правила §4 контракта данных как оракулы измерения: ревизия vs новое событие; кластеризация дублей одного происхождения (синдикации не считаются независимыми подтверждениями); числа вне финансовых границ → отклонение; оригинал не подменяется переводом; страницы антибота/капчи классифицируются blocked/invalid и никогда не становятся авторитетным документом; пустые JS-оболочки — unverified/invalid_content.
- Для семейств без экстрактора (RU/ZH) измерение — на уровне сбора: целостность захвата, классификация, честность даты, язык оригинала, кластер происхождения. Отсутствие экстрактора фиксируется в отчёте как есть, а не маскируется.

## 2. Состав корпуса (ориентир карты: 120 + 20)

Документы — официальные публикации по доменам Pythia (макро/FOMC и ИИ-релизы), захватываются один раз принятой ограниченной машиной захвата в отдельный архив корпуса `/home/pythia/pythia-evidence-corpus` и замораживаются (измерение офлайн и воспроизводимо):

- **EN макро (~44):** заявления FOMC разных лет (~12), статьи из лент ФРС — речи и релизы (~8), снимки EFFR (~6), релизы BLS CPI (~6, если путь получения честно работает; блокировки уходят в негативы), страница GDPNow (~4), релизы ЕЦБ (~8).
- **EN ИИ (~18):** релизы GitHub (DeepSeek и др., ~8), карточки моделей HuggingFace (~6), лидерборд Arena (~4).
- **RU (~26):** релизы Банка России о ключевой ставке и пресс-релизы (~14), публикации Росстата по инфляции (~6), прочие официальные макро (~6).
- **ZH (~20):** релизы НБК (PBOC, ~10), публикации НБС Китая CPI/GDP (~10).
- **Кластер дублей (~6, внутри положительных):** один релиз через 2–3 синдикации — измеряет правило происхождения.
- Точные числа фиксируются манифестом корпуса; недоступность источника честно документируется и состав корректируется внутри ориентира, а не натягивается.

**Негативные контроли (20)** — смесь настоящих захватов и помеченных синтетических: страница-блокировка (403/антибот), стена логина, пустая JS-оболочка (SPA root), 404/410, чужой тип документа для профиля заявления (minutes/projections), обрезанное тело, синдикационная копия под видом независимого подтверждения, документ без даты (дата обязана остаться null), число вне границ (кандидат на отклонение), машинный перевод, поданный как оригинал, и т.п. Синтетика помечается `synthetic_fixture` в метке.

## 3. Метки и разделение

Метка документа: `doc_id, family, language, origin_entity, canonical_url, expected_class (valid|blocked|invalid_content|unverified|rejected:<тип>), expected_facts (числа с единицами, даты, якоря цитат — где есть экстрактор), published_at_expectation (значение или null), cluster_id (для дублей), synthetic (bool), split (tuning|control)`.
Разделение: стратифицированно по семейству×языку×классу, ~60% настройка / ~40% контроль; **контрольная часть заморожена** и не используется для подгонки замерщика; заголовок отчёта — контрольная часть.

## 4. Критерии приёмки R4

1. Манифест корпуса: ≥110 положительных и ≥18 негативных документов с полными метками; языки EN/RU/ZH все представлены; разделение заморожено и записано.
2. Замерщик `python/evaluation/corpus_measure.py` + тесты: офлайн, детерминированно, по замороженным снимкам архива корпуса.
3. Отчёт измерения: ошибки по типам (пропуск факта / неверное число / выдуманная дата / принятая блокировка / пропущенный дубль / подмена перевода / прочее), раздельно настройка и контроль; критические числа: каждое либо верно, либо отклонено — ни одного молча неверного.
4. Все прежние тесты зелёны; production/paper не тронуты; `usable_for_forecast=false`.
5. Отчёт этапа, коммит, приёмка с новым baseline.
