# Pythia R3 Increment 2 (R3.2) — отчёт о реализации

**Дата:** 22 октября 2026. **Исполнитель и архитектор:** Muse (роли объединены решением владельца от 22.10.2026; приёмка опирается на воспроизводимые контроли ниже, а не на самодекларацию).
**Ветка:** `codex/evidence-r32-articles` от принятого baseline `cc118d8` (R3.1 ACCEPTED).
**Решение и план этапа:** `docs/research/2026-10-22/R3_2_DECISION_AND_PLAN.md`.

## 1. Объём работ

Основание дорожной карты: «Контролируемое получение и архивирование связанных official articles; отдельное решение об archive identity/lineage/доступности по времени и подключении article extraction». Решения приняты и записаны в decision record: связанные статьи = документы, на которые ссылаются принятые ленты ФРС; для них — отдельный экземпляр архива на той же машине R2; lineage — аудит получения + манифест извлечения; доступность по времени — receipts/ревизии/`as_of_seq`.

## 2. Реализовано

1. **Реестр источников архива (параметр, не переписывание).** `EvidenceArchive(state_dir, source_registry=None)` и `validate_capture_result(capture, registry=None)`: по умолчанию — принятые канонические 8 источников, поведение не изменено (все 256 прежних тестов зелёны без правок). Явный реестр включает те же строгие правила (членство + точный URL).
2. **Продуктовый модуль получения статей** `python/evaluation/article_acquisition.py` (`pythia-article-acquisition-r32/1.0`): дисциплины принятого драйвера R3.1.9 подняты в поддерживаемый код — супервизор процесса с жёстким дедлайном и SIGKILL, доказанный EOF сжатого потока включая multi-member (исправление N1 действует и здесь: неиспользованных байтов после EOF не остаётся, мусорный хвост отклоняется), лимит тела 2 MiB, анонимный транспорт (trust_env=False, null-cookie-jar), ручные редиректы с воротами, Set-Cookie редактируется. Результат — `CaptureResult`, удовлетворяющий строгим инвариантам архивной границы: complete=True только при полностью декодированном теле с совпадающими счётчиками; любая неудача — честный complete=False с error_msg, пригодный для записи failure-receipt.
3. **Архивирование:** `archive_article()` пишет попытку в архив статей (`record_capture` с явным транспортным probe_result; проверка содержания — на этапе извлечения, что честно отражено в validation_level=transport).
4. **Подключение извлечения:** `extract_archived_article()` читает проверенный блоб через ReadOnlyArchiveReader, строит манифест формы R3.1, расширенный архивной lineage (archive_name, archive_receipt_id, archive_revision_id, archive_seq), и собирает бандл принятым `build_fed_statement_bundle` без изменений.
5. **Тесты** `python/evaluation/tests/test_article_acquisition.py` (7 тестов): канонические ворота по умолчанию отклоняют статьи; ворота реестра статей; жизненный цикл ревизий A→B→A + идемпотентный replay; multi-member захват в архив; обрезанный gzip → failure-receipt без ревизии; повешенный сервер → убитый воркер и честный receipt; сквозной путь на настоящей фикстуре R3.1 → бандл с абзацами, побайтно равными принятым.

## 3. Живой прогон и контроли

Один bounded прогон 22.10.2026 (скрипт `r3/increment2/run_live_archive.py`, результат `article_archive_run.json`): обе статьи FOMC (2026-09-16, 2026-07-29) получены в новый архив `/home/pythia/pythia-evidence-articles` и извлечены из него.

- Receipts: 2, оба complete, status ok / transport. Блобы архива: 2.
- Proofs: 10/10 и 11/11 валидны против архивных блобов.
- Содержание: тексты всех абзацев после нормализации известных волатильных вставок равны принятому извлечению R3.1; хэши цитат равны точно для всех абзацев, кроме абзаца контактов для прессы.
- Принятые архивы R2 не изменились (родительская квитанция ленты читается, хэш блоба на месте).

**Находка о волатильности страницы:** страница заявления ФРС несёт два случайных на каждый ответ элемента Cloudflare — nonce в скрипте в head и токены обфускации email в абзаце контактов. Байтовая идентичность независимых живых захватов на этом сайте невозможна в принципе; архив честно хранит каждый захват как есть (изменение байтов = новая ревизия), а инвариантность содержания судится на уровне извлечения. Заявление по существу (решение, голосование, даты) между захватами неизменно.

## 4. Исключения

- Профиль извлечения — только заявления FOMC; иные типы статей архивируются, извлечение фиксирует typed rejection принятого парсера (обобщение — корпус R4).
- Мониторинг доступности по расписанию не входит в этап (эксплуатация, R8). Production/main/paper/Telegram не тронуты; `usable_for_forecast=false` везде.

## 5. Итог

Полный набор тестов: **263/263 зелёны** (256 принятых + 7 новых). Все критерии приёмки из decision record выполнены. Этап готов к приёмке; при ACCEPTED закрывается и весь R3 (инкременты 0, 1, 2 приняты), следующий этап — R4.
