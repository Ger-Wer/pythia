# Исследование Oracle Markets

Дата: 2026-04-06

## 1. Что это за продукт

`oraclemarkets.io` — это не просто витрина с прогнозами, а публичная AI-forecasting платформа.

По их machine-readable странице `llm.html` сервис позиционируется как:

- бесплатная forecasting-платформа;
- с несколькими AI-агентами;
- с бинарными и multi-choice вопросами;
- с публичными профилями агентов;
- с accuracy tracking через Brier score;
- с интеграцией рыночных данных Polymarket и Kalshi;
- с пользовательской подачей вопросов.

Источник:
- https://oraclemarkets.io/llm.html

## 2. Что у них реально хорошо

### 2.1. Они продают не прогноз, а доверие к прогнозу

Главная сила `oraclemarkets.io` — не в том, что у них “есть AI”, а в том, что они выстраивают вокруг прогноза доверительную оболочку:

- `leaderboard`;
- `accuracy report`;
- `data source transparency`;
- `agent profiles`;
- история прогнозов;
- сравнение с рыночными источниками;
- пояснение методологии.

Для внешнего пользователя это выглядит как полноценная исследовательская система, а не как “LLM что-то посчитал”.

Источник:
- https://oraclemarkets.io/llm.html

### 2.2. Сильная информационная архитектура продукта

Даже из sitemap видно, что у них продукт разложен по понятным публичным разделам:

- `/predictions`
- `/agents`
- `/leaderboard`
- `/accuracy`
- `/data-sources`
- `/research`
- `/roadmap`
- `/api`
- `/llm.html`

Это значит, что у них есть отдельные экраны под:

- discovery;
- trust;
- methodology;
- growth;
- API/distribution.

Источник:
- https://oraclemarkets.io/sitemap.xml

### 2.3. Сильный pattern: отдельный accuracy-layer

По frontend bundle видно, что у них accuracy-слой оформлен как самостоятельный продуктовый блок, а не как “скрипт где-то внизу”.

Там есть:

- overall accuracy;
- Brier score;
- ECE;
- log loss;
- breakdown по domain;
- сравнение `with context` vs `without context`;
- glossary по метрикам;
- radar/domain charts.

Это очень сильный UX-паттерн: метрики не спрятаны в backend-утилите, а вынесены в экран доверия.

Это установлено по shipped frontend bundle `AccuracyReport-QNzrT-i3.js`, то есть это не догадка по лендингу, а вывод по реальной клиентской логике.

## 3. Что у них ещё особенно ценно

### 3.1. Комментарий поверх сигналов

В leaderboard-слое у них есть отдельный комментарий “Top Predictions”, где GPT 5.2 выступает не как основной предиктор, а как комментатор.

Идея сильная:

- один слой делает прогноз;
- другой слой объясняет, какие прогнозы сейчас самые интересные;
- пользователь получает не просто таблицу, а narrative-подачу.

Для оператора это снижает когнитивную нагрузку.

Это установлено по shipped frontend bundle `Leaderboard-C1KXW4UC.js`.

### 3.2. Детальная карточка прогноза как “рабочее место”

По prediction detail bundle видно, что у них в карточке рынка есть:

- история AI probability;
- overlay Polymarket/Kalshi;
- data source transparency;
- agent rationale dropdown;
- explanation how to read chart;
- breakdown по contributing agents;
- confidence block;
- ссылки на источники;
- дополнительные related questions.

То есть карточка прогноза у них — это не страница с цифрой, а место принятия решения.

Это установлено по shipped frontend bundle `PredictionDetail-B_wOWtRX.js`.

### 3.3. Public API и onboarding для внешних агентов

Из API bundle видно, что они думают как платформа:

- внешний агент может отправлять прогнозы по API;
- есть historical datasets;
- есть daily submission contract;
- есть ranking/scoring loop.

Это полезно как мыслительная рамка, но для Pythia сейчас слишком рано.

Это установлено по shipped frontend bundle `API-BelHZek1.js`.

### 3.4. Machine-readable self-description

`/llm.html` — очень хороший ход.

Это:

- SEO-страница;
- документация для LLM;
- короткая truth-source summary;
- способ контролировать то, как AI-системы пересказывают продукт.

Для публичного продукта это очень сильный паттерн.

Источник:
- https://oraclemarkets.io/llm.html

## 4. Что важно понять про различие с Pythia

`Oracle Markets` и `Pythia` — это не один и тот же тип продукта.

### Oracle Markets

- публичная витрина;
- growth/SEO/community-oriented;
- multi-agent public platform;
- рассчитан на массового пользователя;
- продвигает вопрос “какой AI-агент лучше?”.

### Pythia

- приватная операторская система;
- один оператор, закрытый контур;
- no-trading, no-public-marketplace;
- фокус на decision support для владельца;
- Telegram + dashboard как operator console.

Отсюда главный вывод:

Мы не должны копировать `oraclemarkets.io` целиком.  
Нам нужно забирать у них только те паттерны, которые усиливают:

- доверие к системе;
- понятность для оператора;
- скорость разбора;
- интерпретируемость прогноза.

## 5. Что полезно внедрить в Pythia

### 5.1. Отдельный экран качества и доверия

Это самый полезный переносимый паттерн.

Что сделать в Pythia:

- отдельную страницу `Качество`;
- туда вынести:
  - `Brier score`
  - `resolved count`
  - `edge vs market`
  - calibration chart
  - breakdown по категориям
  - glossary простым русским языком

Почему это важно:

- сейчас наши метрики есть, но не живут как отдельный продуктовый слой доверия;
- без этого оператору сложнее понять, “можно ли вообще опираться на систему”.

Приоритет: `P0`

### 5.2. Daily operator digest / “Топ сигналов дня”

Нам очень полезен их паттерн “commentary поверх сигналов”.

Что адаптировать:

- отдельный блок на `Сводке` или `Сигналах`:
  - `3 главных сигнала дня`
  - по 1 короткому объяснению “почему это важно”
  - один операторский комментарий поверх всего прогона

Не как новый forecasting-layer, а как:

- summarization layer;
- операторский гид по разбору.

Приоритет: `P0`

### 5.3. История рынка: Pythia vs рынок

Это очень сильный паттерн из их detail-страницы.

Что полезно внедрить:

- график по рынку:
  - рыночная цена по дням;
  - `Research+R1`;
  - `Naked R1`;
- визуализация сдвига оценки во времени;
- короткое пояснение, как читать график.

Это сделает `Разбор рынка` существенно сильнее, чем просто narrative-блоки.

Приоритет: `P1`

### 5.4. Более сильный transparency-block

У нас уже есть `Источники и исследовательская справка`, но это можно усилить.

Полезно заимствовать:

- явный блок `Что использовано для вывода`;
- явное разделение:
  - свежие источники;
  - ключевые факты;
  - what can falsify the thesis;
  - когда обновлялось в последний раз.

Приоритет: `P1`

### 5.5. Human-readable metric glossary

Oracle Markets хорошо объясняет метрики.

Для Pythia это особенно полезно, потому что:

- пользователь не технический;
- Brier, edge, calibration, confidence без пояснений быстро превращаются в шум.

Нужно сделать:

- glossary/tooltips для метрик на русском;
- отдельный раздел “Как читать метрики”.

Часть у нас уже есть через tooltips, но это надо довести до полноценного слоя.

Приоритет: `P1`

### 5.6. Machine-readable project summary

Если Pythia когда-либо станет полу-публичной или будет часто проходить внешний аудит, имеет смысл сделать свой аналог `/llm.html`.

Но не сейчас.

Для текущего приватного контура достаточно:

- `docs/AUDIT.md`
- `README.md`
- operator docs

Приоритет: `P3`

## 6. Что НЕ стоит внедрять

### 6.1. Публичный multi-agent marketplace

Не нужно:

- публичные профили агентов;
- платформа для внешних агентов;
- внешний ranking ecosystem.

Это резко усложнит продукт и утащит нас из operator-tool в platform business.

### 6.2. User-submitted questions

Это сильный growth-рычаг для публичного продукта, но для Pythia — явный feature creep.

Почему не надо:

- ломает фокус на Polymarket;
- тянет модерацию;
- тянет resolution semantics;
- уводит от текущего критерия успеха: quality on real prediction markets.

### 6.3. Paper-trading / live-trading слой

Для Pythia это особенно не нужно сейчас.

Причины:

- противоречит исходной рамке проекта;
- повышает регуляторный риск;
- повышает операционный риск;
- размывает продуктовый фокус.

Даже если у них это маркетингово выглядит ярко, нам это пока вредно.

### 6.4. Публичная growth-архитектура

SEO-слои, community flows, virality, share mechanics — это логично для Oracle Markets, но не для Pythia на текущем этапе.

Наша цель сейчас:

- качественный private operator tool;
- накопление resolved-данных;
- проверка реального edge;
- понятный рабочий UX.

## 7. Практический вывод для Pythia

### Коротко

У `oraclemarkets.io` стоит брать не “агентов” и не “маркетинговую оболочку”, а три конкретных продукта доверия:

1. `Accuracy / Quality page`
2. `Top signals commentary layer`
3. `Market history chart with comparison to market`

### Рекомендуемый порядок внедрения

1. Добавить в Pythia страницу `Качество`
2. Добавить на `Сводку` блок `Главные сигналы дня`
3. Усилить `Разбор рынка` историческим графиком `Research+R1 / Naked / рынок`
4. Довести metric glossary/tooltips

## 8. Вывод в одном абзаце

`Oracle Markets` — это хороший продуктовый референс не потому, что у него “много AI”, а потому что он очень хорошо упаковывает доверие, интерпретируемость и публичную читаемость прогноза. Для Pythia полезнее всего заимствовать у них не публичную платформенность, а доверительный слой: отдельный accuracy-экран, commentary поверх сигналов и более наглядную историю рынка в detail view. Всё, что связано с публичным multi-agent marketplace, user-submitted questions и trading-инфраструктурой, для Pythia сейчас скорее вредно, чем полезно.
